# 北京:A(条件需求 ML)↔ B(可微分 ABM 供给均衡)耦合与拥堵内生性

(2026-06-06。本文交代:拥堵的内生性在模型里落在哪、A 单独处理到哪、为什么要 B、A↔B 的接口是什么。
是 [01_identifiability_reliability.md] §6(mode)的延伸,也是 B 模型(未来/搭档工作)的蓝图。)

## 0. 一句话核心

**A 学的是"现在大家怎么选",B 问的是"路况变了大家会不会改选"。连接两者的旋钮是 β_t(对时间的敏感度);
A 自己看不准这旋钮该拧到几(被拥堵带偏),B 把供给侧(拥堵函数)设出来后,这旋钮才解得出。**

## 1. 分工与状态

| | A:条件需求模型(本仓库 v4 ML) | B:可微分 ABM(单独工程,搭档/未来工作) |
|---|---|---|
| 干什么 | 给定出行时间,算谁去哪 + 怎么走 | 流量→压路网→涌现拥堵→更新时间,解供需均衡 |
| 出行时间 | **外生输入**(部分均衡) | **内生**(由均衡决定) |
| 状态 | **已完成**(CPC 0.6926,mode 锚定,occ typed-mass) | 未实现 |

**A 不依赖 B 才算"完成"。** A 作为条件需求模型是完整、可独立成文的;拥堵内生性是 A 的**明示边界**,B 是闭合它的搭档。
是否实现 B,取决于 paper 要不要 claim "改变出行时间的反事实"(新地铁/拥堵收费/扩容)或"纠正后的 β_t"。

## 2. 拥堵内生性落在三个选择层的哪一层

| 选择层 | 现实 | A 里的位置 |
|---|---|---|
| 路径选择 | 堵了换路 | ❌ 不建模。高德 t_matrix 已把路由拍平,埋在数据里 |
| 方式选择 | 堵了弃车 | ✅ 直接咬这里。只有车时间分时段(高峰 t_obs / 夜间 t_ff),公交步行固定 |
| 目的地选择 | 堵了换近的 | ✅ 经嵌套 inclusive value 二手传导 |

**拥堵 = 高峰车时间相对自由流的上浮,主战场是 mode,经 IV 渗到 destination;路径不建模。**

## 3. 两个**不要混**的识别问题

A 的 mode 有两件事识别不好,**病因和解法都不同**,过去常被揉一起:

| | 是什么 | 病因 | 解法 |
|---|---|---|---|
| **mode 水平**(asc:现在多少人开车) | 选择的**截距** | OD 方式合并、无方式标签 | **外部锚**(刷卡+普查 .21/.35/.44) |
| **β_t 斜率**(推一把滑多远) | 选择对时间的**导数** | 拥堵**同时性**偏误 | **B**(供给侧识别) |

⚠ §01 的 profile span 0.035 测的是 `asc_transit`(**水平**),**不是 β_t**(斜率)。别拿 0.035 当 β_t 的证据。

## 4. β_t 为什么在 A 里有偏 —— 用供需图讲清(这是本文核心)

经济学最老的一张图,套上模型:

```
   时间 T (=价格)
     │
     │ ＼ A=需求曲线 Q=D(T): 时间越高去/开车越少
     │   ＼          斜率 = β_t  ← 要识别的
     │     ╲    ╱ B=供给曲线 T=S(Q): 人越多越堵 (拥堵函数)
     │      ╲ ╱
     │      ╱ ╲___ ●  观测到的 (Q,T) = 两曲线交点
     │    ╱
     └──────────────── 流量 Q (=数量)
```

经典内生性:你只看到一堆**交点**,分不清是需求在动还是供给在动 → 直接用观测时间估 β_t 会有偏。

**关键是看清谁在动、描出来的是哪条线:**

- **高峰 vs 夜间(时段变化)= 需求在平移、供给不动。** 高峰一堆人通勤(需求右移),夜里几乎没人(需求左移),
  而路还是那条路(容量没变,供给曲线固定)。两个交点(高峰高 Q 高 T / 夜间低 Q 低 T)**贴着供给曲线滑**
  → **时段变化描的是供给曲线(拥堵函数),不是需求。** 拿它识别 β_t 是用反方向。
- **要识别需求斜率 β_t,得让供给动、需求不动。** 干净的供给侧推手是 travel time 里**外生**的那部分:
  **跨 OD 的自由流时间 / 距离 / 容量** —— OD 对 X 比 Y 远是地理原因(跟需求无关),它让不同 OD 时间不同,
  需求沿这些外生差异响应,β_t 才露出来。

**A 为什么做不到这个分离:** A 的输入里**有**外生变化(夜间 t_ff、距离 log_d),但 A **不建供给侧**——
它不知道 `t_obs = t_ff + 拥堵(Q)`,把高峰拥堵时间当"那个时段的时间"囫囵用,
干净的自由流识别被高峰拥堵期的脏变化**污染混在一起 → β_t 有偏**。这是 bias,不是无信息。

**偏的方向(可证伪检查):** 高峰**又堵又人多**(高 T 高 Q 同时出现),模型看到"流量高时时间也高",
把真实的负时间效应**往零衰减** → **β_t 被低估(偏向 0)**。
预期:接 B、用干净外生变化重估后,**β_t 应比 A 单估更负**。这是个明确的验收点。

## 5. B 怎么救 —— 不是给外生工具,是把供给曲线设出来

**B 不提供外生工具变量(IV),而是显式设定拥堵(供给)函数,做结构联立 / control-function 识别。**

- 时段变化(需求平移、供给固定)→ 把**供给曲线定住 / 验证**(B 也可直接用工程 BPR + 容量数据**设定**它);
- 供给一旦摆明,在**均衡条件 + 跨 OD 外生自由流/距离/容量变化**下,需求斜率 β_t 解得出;
- 拥堵函数**吸收掉内生那部分**,A 分不开的"外生自由流 vs 内生拥堵",B 因为建了 S(Q) 而能分开。

> **承重墙假设:β_t 的可信度押在"拥堵函数设对了"上**(volume-delay 形式是否合理)。
> 论文要正面辩护这个设定,**不能写成"我有个外生拥堵工具所以无偏"**——那是 IV 话术,与此路子不符,会被拆穿。

**与伦敦 Deep IV 的区别:** 伦敦想找真外生工具(天气),因小时聚合对不齐失败。
B 不是"找更好的工具",是"干脆把供给曲线本身设出来"——两种不同的识别策略,别混说成"B 找到了工具"。

## 6. A↔B 接口规格(B 的蓝图)

**A 要暴露给 B 的:对出行时间可微。** A 的效用 `V_lower_car = (β_t0+β_t1·log_d)·t_car`
光滑进 `IV = logΣexp(V_lower/λ)` → `V_dest += λ·IV` → `logP = V_dest - segment_logsumexp`。
所以 `∂logP/∂t_car` 解析存在,B 能把拥堵沿这条链反传:
```
t_car ──► V_lower_car ──► IV ──► V_dest ──► P(选择)
（只有车时间随拥堵动；公交/步行 A 里固定，B 第一版可只让 t_car 进均衡）
```
**这点架构已满足,A 不用改。**

**B 要提供的:**
1. 拥堵(供给)函数 `S(Q)`(BPR 类 volume-delay)+ 路网容量数据;
2. 均衡求解器(解 流量↔时间 不动点);
3. 把 A 的选择概率耦合进流量装载;
4. 联合识别 β_t(供给侧外生变化 + 均衡条件)。
这是**新项目级**工作,不是改 A。

## 7. 落到 paper 的写法(可直接用)

> A 是条件需求模型:给定 travel time 估选择,β_t 是时间敏感度。A 的输入含外生变化(自由流、距离),
> 但 A 不建供给侧,无法把外生自由流与内生拥堵 t_obs 拆开,**β_t 因拥堵同时性而有偏(偏向 0)**——
> 这是偏误,不是无信息;且与 mode **水平**的不可识别(因 OD 方式合并、由外部锚解决)是**两回事**。
>
> B(可微分 ABM)不提供外生工具,而是**显式设定拥堵(供给)函数**:时段变化(需求平移、供给固定)
> 用于定住/验证供给曲线;在该设定 + 均衡条件下,识别需求斜率 β_t 的是**跨 OD 外生自由流/距离/容量变化**,
> 拥堵函数吸收内生部分。**β_t 可信度取决于拥堵函数设定**(承重墙假设,需正面辩护),不写成 IV 无偏话术。
>
> 验收:接 B 后干净的 β_t 应比 A 单估更负(纠正高峰同时性的零方向衰减)。
